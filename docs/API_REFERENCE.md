# API reference

Development base URL: `http://localhost:5000/api`.
Authenticated requests include the session cookie. JSON mutations use
`Content-Type: application/json` and the configured `Origin`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | Backend availability |
| POST | `/auth/register` | Register with name, email and password |
| POST | `/auth/login` | Authenticate and establish a session |
| GET | `/auth/me` | Current user's public account information |
| POST | `/auth/logout` | Destroy session and clear its cookie |
| GET | `/transactions` | Owner's records, matching totals and category breakdown |
| POST | `/transactions` | Create an owned income/expense |
| GET | `/transactions/:id` | Owner-scoped transaction details |
| PUT | `/transactions/:id` | Replace all editable transaction fields |
| DELETE | `/transactions/:id` | Delete owned transaction and embedded receipt |
| GET | `/budgets?month=YYYY-MM` | Monthly income/spending and user's budgets |
| PUT | `/budgets` | Create/update a month/category limit |
| DELETE | `/budgets/:id` | Remove owned budget; transactions stay unchanged |
| GET | `/documents?month=YYYY-MM&page=1` | Owner's document records; 10 per page |
| POST | `/documents` | Create a transaction with an embedded receipt |
| GET | `/documents/:id/file` | Authenticated download of owner's file |
| DELETE | `/documents/:id` | Remove attachment while keeping transaction |

## Transaction input

```json
{
  "type": "expense",
  "amount": "150.25",
  "category": "Food",
  "description": "Lunch",
  "date": "2026-10-29"
}
```

Amount is a decimal **string** with at most two fractional digits. The server converts
it to integer cents. The owner comes from the session, never from a submitted `user` field.

Income categories: Salary, Freelance, Gift, Other.
Expense categories: Food, Transport, Housing, Bills, Education, Health, Entertainment, Other.

## Transaction query parameters

| Parameter | Accepted values |
| --- | --- |
| `q` | Literal case-insensitive category/description search, up to 100 characters |
| `type` | `income`, `expense`, or omitted |
| `category` | Valid category for the chosen type, or omitted |
| `from`, `to` | Inclusive calendar dates, `YYYY-MM-DD` |
| `sort` | `date-desc`, `date-asc`, `amount-desc`, `amount-asc` |
| `page` | Integer 1–999999; adjusted to the last available page when needed |
| `limit` | 5, 10, 20 or 50 |

Totals and category breakdown include every matching record, not just the current
page. Overview requests omit filters, so its totals remain independent.

## Budget input

```json
{ "month": "2026-10", "category": "Overall", "amount": "50000.00" }
```

Saving the same owner/month/category updates that limit. Budgets do not create expenses.

## Document input

Include normal transaction fields plus `uploadId` and:

```json
{ "file": { "name": "receipt.pdf", "base64": "BASE64_FILE_BYTES" } }
```

`uploadId` is generated by the browser for a submission. An identical retry returns
the original result; reuse with changed content returns 409. The example Base64 text
above is illustrative, not valid file data. Actual file size is limited to 2 MB.

## Common responses

- 200: successful read/update/delete or accepted identical upload retry.
- 201: registration, transaction or document created.
- 400: invalid input, query, month or ID format.
- 401: no valid authenticated session.
- 403: state-changing request has an unapproved Origin.
- 404: record missing or unavailable to this owner.
- 409: duplicate email or changed content under an existing upload reference.
- 413: request body exceeds its configured limit.
- 429: request rate limit exceeded.
- 500: unexpected server error.
